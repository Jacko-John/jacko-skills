# 实验设计

先找到一个值得写下来的结果，再用别人挑不出毛病的方式证明它。

## 立场

1. **平庸的实验比失败的实验更贵。** 跑了三十组、每组都"略好一点"，等于三十次没提供信息。
2. **效应小到要多跑几组 seed 才看得见，通常该换维度，不是加算力。** 去更难的子集、更长的时间尺度、更极端的分布里找，那里差距会被放大。
3. **主动设计能杀死自己方法的实验。** 活下来的结论才算数；没被攻击过的结论只是期望。
4. **对照越狠，主张越敢提。** 纪律是为主张服务的，不是用来替代主张的。
5. **探索阶段不受确认阶段的纪律约束。** 先允许乱来，才谈得上严谨。流程不该成为不敢试的借口。

## 两种模式

|  | 探索 | 确认 |
|---|---|---|
| 目的 | 找现象、找边界、找反例 | 把现象变成能辩护的结论 |
| 规模 | 小、快、多铺几个 | 足量、重复、受控 |
| 变量 | 一次动几个无妨 | 一次只动一个 |
| 失败 | 正常，是信息 | 如实报告 |
| 产出 | 假设、机制猜想、可疑之处 | 论文里的结论 |

唯一的铁律：**探索得到的是假设，不是结论。** 写进论文或对外报告之前，必须在确认模式下独立复现一次。

## 流程

**0　定义赢。** 一句话：什么结果会改变我对这个问题的看法。写清效应要多大、在哪些工况赢、和谁比才算数。目标定小了，实验设计会跟着变小。

**1　探边界（探索模式）。** 先去方法该输的地方——连那里都不输，说明还没理解它；再去它该大赢的地方。看机制、错误类型、失败样本，不只看总分。探针要 15 分钟内出结果，出不来先修测量工具。预期之外的结果优先追。

**2　立契约。** 每条主张 → 一句能被数据否定的命题 → 一个失败信号 → 匹配的证据形态（算法：对照+消融；系统：真实负载端到端；理论：证明+数值；实证：统计检验；训练：多种子均值方差）。拿不出失败信号的是愿望，不是主张。

**3　对齐对照。** 每个实验填满五项：唯一自变量、固定项、基线、指标及算法、成功阈值与重复次数。基线挑"输给它我不会惊讶"的那个，来源按官方代码 > 原文数字 > 自实现排序，且要在同预算内调到最好。数据与划分、评测实现、调参预算、算力预算、环境五处必须一致；差异表逐条写理由，写不出影响的算未控制。

**4　记账。** manifest 记配置、代码与数据版本、种子、环境、状态。一次一个变量。随机性敏感就跑多次，报均值±标准差，不在 seed 里挑最好；差距接近噪声（<1% 或 2σ）就做显著性检验。失败、异常、废弃配置全部留档。

**5　回填与攻击。** 每个结果判定支持 / 不支持 / 无关，然后站到对手位置：还可能是什么别的因素？抽掉最强那条证据，结论还在吗？不支持就改主张，不改数据。反常结果是资产，写进正文。

## 常见做法 / 更值得做的做法

| 常见做法 | 更值得做的 |
|---|---|
| 在通用 benchmark 上挤 0.5% | 找一个现有方法系统性失效的工况，在那里建立优势 |
| 消融证明每个模块都有用 | 消融找出模块在什么条件下有害、在什么条件下可以删 |
| 只展示成功 | 主动画出失效边界，可信区反而更大 |
| 单次最好结果 | 均值±方差 + 显著性 |
| 基线用默认配置 | 同预算调到最好再比 |
| 跑完再决定报什么 | 跑之前定成功阈值，也定放弃条件 |
| 结果不支持主张就换指标 | 换主张，或者承认它不成立 |
| 实验做完再想怎么讲故事 | 契约阶段就想清楚每个实验对应哪一句结论 |

## 何时停下来问用户

- 主张翻译不成可证伪的命题。
- 基线不可得，协议无法对齐。
- 预期差异小于可测噪声，需要换任务、指标或规模。
- 预算撑不起契约要求的重复次数。
- 结果否定了核心主张——这是升级信号，不是坏消息。

## 交付物

契约表、探针记录（含失败）、实验矩阵、公平性差异表、run manifest、结果回填表。它们同时是论文实验章节、技术汇报和 rebuttal 的原材料。
