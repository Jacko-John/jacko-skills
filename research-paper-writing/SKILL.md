# CCF 会议论文写作

## 两层结构

这个 Skill 只内置两层方法：

1. **通用八股路线**：规定一篇论文需要完成哪些论证功能，以及这些功能怎样衔接。
2. **动态写作细节**：针对当前论文、研究方向和目标会议主动调研，把可观察到的写法总结到 `writing-details.md`。

通用路线不规定固定句数、段数、页数、模块数量或某类会议的专属结构。这些细节来自当年官方要求和对相近论文的实际阅读，而不是预设模板。

## 通用八股路线

写作的第一性问题是**对齐**：问题引出挑战，挑战驱动设计，设计产生可检验的主张，证据支撑主张。
以下路线规定论证功能，不要求机械地按章节顺序起草。

| 部分 | 要完成的论证功能 |
| --- | --- |
| Title | 准确识别研究对象与主要贡献，范围不超过正文。 |
| Abstract | 从背景收紧到问题与缺口，给出关键洞察、方法和最重要的证据，让读者不看正文也知道做了什么、为何值得做、效果如何。 |
| Introduction | 建立问题的重要性，解释现有路线为何仍有未解决的挑战，提出本工作的洞察与方案，并用贡献和关键结果收束。 |
| Background / Related Work | 提供理解论文所需的背景；按问题或技术路线定位已有工作，说清与本工作的关系及实质差异。两者是否独立、前后如何安排由具体写法决定。 |
| Method | 先建立整体视角，再交代设计及其依据；说明各设计如何回应挑战，并给出复现或理解所需的形式化、算法、实现或分析。 |
| Experiments / Analysis | 先交代评估或分析设置，再给出整体结果，随后用针对性证据检验设计选择，最后分析开销、边界、失败或其他解释。 |
| Discussion / Limitations | 说明适用范围、假设、局限和设计取舍，不把限制包装成贡献。 |
| Conclusion | 收束问题、方法和已被证据支持的结论，不引入正文没有的新主张。 |

“问题—挑战—方法—证据”是关系，不是数量公式。一个设计可回应多个挑战，多个设计也可共同回应一个挑战；未知内容可以保留标记，不能为填满八股而编造。

## 动态文件：`writing-details.md`

默认把文件放在当前论文工作目录；用户指定路径时使用指定路径。多篇论文共用工作区时，分别放在各论文目录，避免相互覆盖。

这个文件是**当前论文的调研笔记和写作约定**，不是放之四海皆准的会议规则，也不是论文正文。

- 已存在且仍适用于当前目标和任务时，先读取并复用，不重复调研。
- 目标会议、论文类型或任务发生变化，或者现有细节缺少来源、过于笼统时，补充调研并更新。
- 文件不存在而任务涉及构思、起草或结构性改写时，有检索和写文件能力就主动调研并创建，不等待用户提供范文。
- 只做局部语言润色、现有细节已经足够时，不必为形式创建或更新文件。
- 没有联网或全文访问能力时，使用可获得的本地材料并说明限制；不能假装调研过。

## 写作工作流

1. **读取现状**：明确研究材料、已有稿件、用户目标、目标会议和当前任务；已有 `writing-details.md` 时一并读取。
2. **按需调研**：结构性任务主动寻找相近论文，优先目标会议。读取 `references/research-method.md` 和当前任务涉及的分节观察清单，不凭标题或记忆模仿。
3. **沉淀细节**：参考 `references/writing-details-template.md`，将观察、来源和对本稿的用法写入 `writing-details.md`。区分官方要求、共同模式和单篇做法。
4. **完成当前交付**：用通用八股检查论证闭环，从细节文件选择适合本研究的写法，再起草或改写。可以逐节，也可以处理全文；输出语言和格式服从用户与目标论文。
5. **回看并校正**：检查主张是否有适当证据、章节是否共同服务贡献、细节是否确有来源。发现新的重要写法时同步更新细节文件。

不必每次展示完整流程或固定审计附件。优先交付用户需要的正文、修改或诊断；创建或更新细节文件时，说明路径和主要参考来源。

## References：调研观察清单

这些文件告诉模型**调研时看什么、如何记录、写完后检查什么**，不提供预设的会议答案。按当前任务加载相关文件，不必全部读取：

- 调研方法与来源分级：`references/research-method.md`
- 动态细节文件模板：`references/writing-details-template.md`
- Title 与 Abstract：`references/abstract.md`
- Introduction：`references/introduction.md`
- Background 与 Related Work：`references/related-work.md`
- Method：`references/method.md`
- Experiments 与 Analysis：`references/experiments.md`
- Discussion 与 Limitations：`references/discussion.md`
- Conclusion：`references/conclusion.md`
- 图、表与证据呈现：`references/figures-tables.md`
- 全文与投稿前自审：`references/checklist.md`

## 红线

1. 不虚构读过的论文、官方要求、引用、实验结果或来源；无法访问全文时明确说明。
2. 不复制参照论文的文字、图表或独特表达，不通过同义改写掩盖拼贴；具体观点和发现按学术规范归引。
3. 参照论文提供写法，本研究材料和可核查来源决定可以声称什么。
4. 当年官方要求优先于观察到的会议惯例；本研究的论证需要优先于任何八股模板。
5. 不把增量包装成新范式，不隐瞒局限，不让 Title、Abstract 或 Conclusion 超出正文证据范围。
