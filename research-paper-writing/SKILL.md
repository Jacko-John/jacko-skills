# 写论文

论文不是把做过的研究汇报一遍，是让一个忙碌、默认怀疑你的陌生人相信一件事。

## 立场

1. **审稿人在找拒绝的理由。** 动笔前先替他写完三条，再决定哪里要额外用力。
2. **一篇论文只讲一件事。** 章节是同一论断的不同论证角度，不是八个格子。
3. **Title、Abstract、Intro、主图、主表决定生死。** 评审十五分钟内读完这些就可能定结论，其余部分是防守。
4. **惯例降低阅读摩擦，不替代判断。** 写法可以学别人，主张只能从自己的结果里长出来。
5. **先写证据撑得住的版本。** 不要先写愿景再去找证据。

## 主线：一句话主张

整篇论文回应的只有一句："在___条件下，___因为___，从而___。"

- 写不出这句话，说明研究还没想清楚。改研究，不改措辞。
- 这句话不让人意外，论文大概率平庸。此时该回头看实验设计，而不是润色。
- 每一节都要能说出：它为这句话增加了哪一块支撑。

## 章节分工

| 部分 | 读者读完要相信 | 最容易写坏的地方 |
|---|---|---|
| Title / Abstract | 这件事值得读，而且只有这样做才成立 | 承诺超出正文；方法名先于问题出现 |
| Introduction | 问题真实、现有路线有具体缺口、你的洞察有机会补上 | 缺口写成"别人没做过"，而不是"别人为什么做不到" |
| Related Work | 你了解这片地，并且和最接近的工作有实质区别 | 逐篇罗列；把差异说成对方的缺陷 |
| Method | 设计是被挑战推出来的，不是模块堆出来的 | 先讲细节后讲全局；把直觉写成已证明的结论 |
| Experiments | 比较公平，结论在噪声之外，也清楚何时失效 | 基线不调；只报有利子集；把性能差当成机制证明 |
| Discussion / Limitations | 你知道边界在哪、付了什么代价 | 局限写成未来工作；回避最可能的攻击点 |
| Conclusion | 记住一件事 | 复读摘要；引入正文没有的主张 |

实验怎么做、对比怎么对齐，归 `experiment-design` 管；这里只负责把已有的证据讲清楚。

## 流程

**0　立主张。** 写出那句话，读出来。它不让人意外，就回到研究本身。

**1　写攻击面。** 三条最可能被拒的理由，每条指名哪一节负责反驳。写不出反驳的那条，就是证据缺口。

**2　排证据。** 每条主张对应哪张图、哪张表、哪个数字，落在第几节。缺口先补；补不了就降级主张，不要留给审稿人发现。

**3　按影响力起草。** Abstract → Intro → 主图主表 → Method → 其余。Title 最后定，因为它要概括已经写完的东西。

**4　需要时才对照。** 拿不准某节的惯例时，读三到五篇目标会议论文，看结构与详略，不看句子，半天内结束。只有官方文件能定义硬性要求（页数、模板、匿名），别把他人习惯当规则。

**5　自审。** 回到第 1 步的三条攻击：正文正面回应了吗？抽掉最强的那条证据，结论还在吗？Title、Abstract、Intro、Conclusion 说的是同一件事吗？

## 项目便签（可选）

跨会话或多人协作时，在工作目录留一个 `paper-notes.md`，四行够用：

- 一句话主张
- 三条拒稿理由，及各自由哪一节反驳
- 证据缺口：缺什么，补不了时把主张降成什么
- 目标会议的硬性要求与来源

它不是正文，也不是惯例档案。写完就更新，别让它和稿子说两套话。

## 常见做法 / 更值得做的做法

| 常见做法 | 更值得做的 |
|---|---|
| 先读十篇相近论文再动笔 | 先写一版论证，再用三篇做对照检查 |
| 从 Intro 顺写到 Conclusion | 先写决定生死的五样：Abstract、Intro、主图、主表、Title |
| 每节写得"完整" | 每节只承担一个反驳任务 |
| 用"显著提升""首次"制造分量 | 让数字和机制说话，强词只在能兑现时用 |
| Related Work 逐篇罗列 | 按路线分组，只与最接近的工作正面比较 |
| 局限写成未来工作 | 写清触发条件、后果和依据 |
| 追求八股齐全 | 追求一个让人记住的论断 |
| 照抄目标会议的结构 | 抄阅读摩擦，不抄论证 |

## 红线

1. 不虚构文献、数字、来源。核对不了的标为待确认，不写进正文。
2. 参照论文提供写法，研究材料决定能声称什么。
3. Title、Abstract、Conclusion 不得超出正文证据。
4. 不复制他人文字、图表和独特表达。

## 何时停下来问用户

- 说不出一句话主张。
- 证据缺口补不上，主张也降不下来。
- 论文类型与目标会议的评审口味冲突。
- 用户要求的主张超出材料能支持的范围。

## 交付物

一句话主张、三条攻击面、证据—位置表、正文。前三项是写正文的依据，也是 rebuttal 的底稿。
