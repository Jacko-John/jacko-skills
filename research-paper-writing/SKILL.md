# 写论文

论文是写给人看的：用符合目标会议品味的叙事、低理解负担的清晰讲解和经过推敲的专业语言，让读者轻松而信服地理解你的工作。

## 立场

1. **叙事大于防守。** 好论文靠清晰的动机、有力的洞察和坦诚的证据赢得读者，而不是每节竖一块盾牌去堵审稿人。挑剔式自审留在收尾，不主导正文写法。
2. **迎合目标会议的品味。** 不同社区在乎的问题、证据形态和故事弧线不同——系统会看重真实瓶颈与系统权衡，算法会看重机制洞察与严格消融，理论会看重精确假设与证明边界。先摸清目标会议认可什么，再决定怎么讲手头的材料。
3. **不假设读者有你的上下文。** 你和这个项目共处了几个月，读者是第一次读到它。每一个未解释的术语、突然跳出的公式、没交代动机的设计，都在消耗读者耐心。
4. **主张随结果流动，以稿件和最新数据为准。** 补充实验不及预期或冒出更亮眼的现象时，叙事和主张要跟着最新证据走；稿件与当前实验结果本身就是唯一事实源，直接在正文与对话中迭代更新。
5. **用语既要专业，也要好读。** 学术读者里有大量忙碌的非英语母语者。好文字不是词汇考卷，而是术语精准、句式干净、逻辑一眼看透。

## 叙事主线与动态调整

整篇论文最终只回答一件清晰的事：为什么这个问题值得被解决、现实中哪里真正卡住了、你的核心洞察如何改变现状、现有结果说明了什么以及边界在哪。

- 主线是活的：补出更好效果时放大真正有力的发现，结果不如预期时及时收窄适用条件、调整定位，让叙述永远贴合当前最好且站得住的证据。
- 如果说不清为什么做这件事、或者它究竟带来了什么新认知，往往说明问题定义或实验本身还没想透——先回去理清研究或对齐实验，而不是靠修辞硬撑。

## 读者体验与理解负担

把读者当成跨方向、刚翻开第一页的同行专家，主动帮他省力气：

- **先给地图，再进细节。** 每节开头交代它回答什么问题、各段怎么推进；先给直觉和具体例子，再给形式化定义、符号和伪代码。
- **零前置泄漏。** 缩写、符号、自定义术语和指标在首次出现处随手定义清楚，不默认读者记得前文或前人论文里的简称。
- **解释设计动机，不列模块清单。** 讲方法时先说明遇到了什么限制或矛盾，再引出设计选择；读者看到的是“不得不如此”的推理，而不是“我们加了三个模块”。
- **段落与图表自洽。** 每段只承载一个核心意思，首句点明本段角色，段间过渡交代因果或转折；主图、主表配独立可读的 caption，让只扫图表的人也能抓住主线。

## 写作语言：专业且照顾非母语读者

- **术语精准、立场克制。** 使用领域公认的标准说法，不造生僻同义词，不用口语或空泛拔高词（如无依据的 *significantly*、*novel*、*first*、*dramatically*）；结论力度严格匹配证据（区分“证明”“表明”“观察到”）。
- **句式直接、结构好扫。** 一句尽量只说一个判断，主语与核心动词靠拢，少用多层嵌套从句、过长前置定语和堆叠的名词化短语，长短句交替推进节奏。
- **命名一以贯之。** 同一个概念、模块或指标全篇用同一个词，不做“同义词替换”式炫技；避免用孤立的 *this* / *it* / *such* 指代整段话，补出具体名词（如 *this bottleneck*）。
- **选词平实、去 AI 腔。** 优先使用准确规范的通用学术词，避开生僻文学词汇、俚语和双关；删掉空洞开场、机械排比和段尾强行升华的套话。

## 章节分工

| 部分 | 读者读完要获得 | 最容易写坏的地方 |
|---|---|---|
| Title / Abstract | 一眼看懂问题价值、关键思路与核心结果，愿意继续读 | 还没说清问题先抛方法名；承诺超出正文 |
| Introduction | 痛点真实、前人卡在何处（而非只是“没做过”）、你的洞察为何自然有效 | 像流水账一样堆背景；动机到方法之间有逻辑断层 |
| 主图 / 主表 | 三十秒看懂方法与既有思路的分歧，以及核心定量优势 | 主图是一堆看不出机制的黑盒方框；主表只报有利子集且 caption 读不懂 |
| Background & Motivation | 看懂必要前置背景，并用实测现象或具体反例信服“为什么常规方案行不通” | 只讲常识不摆实质障碍；或把 Motivation 写成空喊重要性（视会议习惯独立成节或紧接在 Method 前） |
| Related Work | 看清你的工作在学术谱系中的位置，以及与最接近工作的实质区别 | 按年份逐篇报菜名；把设计取舍写成贬低他人 |
| Method | 顺着挑战与权衡理解整体思路，再看懂关键机制与复现细节 | 先甩公式细节再讲全局；把未验证的直觉写成既定事实 |
| Experiments | 相信对比公平、结论真实，并看清机制生效条件与失效边界 | 基线没调好；只报总分不看分解与机制；回避反常结果 |
| Discussion / Limitations | 明确适用条件、代价与边界，感到作者对自身局限诚实清醒 | 把明显局限包装成轻飘飘的“未来工作” |
| Conclusion | 记住一个清晰准确的核心结论 | 机械复读摘要，或引入正文没有的新主张 |

## 流程与协同 Skills

多节起草、结构性改旧稿或投稿前检查时，按 [references/workflow.md](references/workflow.md) 的六个阶段推进（Stage 0 分流诊断 → Stage 1 会议品味与硬边界 → Stage 2 叙事骨架对齐 → Stage 3 分节起草与新结果回流 → Stage 4 理解负担与语言精修 → Stage 5 投稿前全检）；若只是单句或单段局部润色，直接对照本文件标准执行即可。

写作过程中遇到以下环节时，主动调用仓库内对应的协同 skill：

- **`grasp-the-principal-contradiction`**：大改旧稿、面临矛盾的审稿/合著者意见、篇幅严重超限、或新实验动摇主线时，先找出牵一发而动全身的主要矛盾，决定改动的优先次序。
- **`experiment-design`**：写 Motivation 缺实测证据、写 Experiments 发现基线未对齐、差距太小或存在证据缺口时，转入实验设计与可信度核查。
- **`humanizer`**：在语言精修阶段消除 AI 写作痕迹（*not X but Y*、强行拔高的段尾句、空洞排比等），按技术文本与文件/嵌入模式保留专业术语、精确数字和 LaTeX 语法。
- **`workspace-cleaner`**：画图、统计或编译检查结束时清理临时脚本和中间废料，保持论文目录干净。

## 红线

1. 不虚构文献、数字、实验设置或来源；核对不了的明确标出待确认，不写进正文。
2. 除非用户明确要求，不在工作区新建独立大纲或辅助文档。
3. Title、Abstract、Conclusion 不得超出正文已有证据。
4. 不复制他人文字、图表和独特表达。

## 何时停下来问用户

- 新实验结果与原定主张冲突，需要确认往哪条叙事主线收束。
- 现有证据撑不起目标说法，需要决定是补实验还是收窄主张。
- 关键数字、对比设置或术语定义缺失，继续写只能靠猜。
- 论文类型与目标会议的审稿品味存在明显错位。
